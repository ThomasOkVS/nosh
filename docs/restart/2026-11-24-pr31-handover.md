## Next, in order

### 1. Fix CI on PR #31

`pnpm test` fails in 5 server suites: `app.security`, `main`, `auth/cookie`, `auth/routes` and `http/spa`. Each fails with:

> Failed to resolve entry for package "@nosh/shared"

- **Why it passes locally:** a `shared/dist` built earlier exists on the dev machine. CI runs the tests before `pnpm build`, so there is no `dist` there.
- **Likely cause:** `server/vitest.config.ts` sets only `resolve.conditions: ["source"]`. Server tests run in Vitest's SSR/node environment, which uses `ssr.resolve.conditions` (Vite 6+), so the `source` export of `@nosh/shared` is ignored and the default (`./dist/index.js`) is used.
- **Fix:** add the `source` condition to the SSR resolve conditions in `server/vitest.config.ts`. Check `shared`'s Vitest config too.
- **Prove it the way CI runs:** delete `shared/dist`, then run `pnpm test`.
- **Don't** paper over it by building before testing in CI. Tests must run on source.

Push the fix to `claude/skeleton-auth` and let CI rerun. Merge only when `check` and `image` are green. Use a merge commit, like the earlier PRs; that is the owner's standing instruction for #31.

Merging starts the `publish` job, which pushes `ghcr.io/thomasokvs/nosh:main` and `:<sha>`. That is a new image name, so Watchtower and v1 are not affected.
