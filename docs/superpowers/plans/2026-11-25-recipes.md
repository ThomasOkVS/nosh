# Recipes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recipe CRUD with one cover photo (plus a card-sized copy), the
library, recipe and form screens in the §7 style with a designed empty
state; then, in a second PR gated on the host firewall, the shared SSRF
fetch guard and attaching a photo from a URL.

**Architecture:** A `server/src/recipes/` module (repository + Hono routes)
and a `server/src/images/` module (byte sniffing, HEIC conversion, card
copy, disk store), mounted in `createApp` behind `requireAuth`. Shared zod
schemas and cap messages in `shared/src/recipes.ts` are used by the server
and by the form's submit transform. The SPA gets `app/src/recipes/` (queries,
mutations, form logic) and three routes. PR2 adds `server/src/net/safeFetch.ts`
and one route.

**Tech Stack:** as the skeleton, plus `file-type`, `heic-convert`, `sharp`
(server); `react-hook-form`, `@hookform/resolvers`, shadcn `alert-dialog`,
`dropdown-menu` and `sonner` (app); `undici` (PR2, if the builder keeps it).

**Spec:** [recipes design](../specs/2026-11-25-recipes-design.md) (read it
first: §4 says which criteria are in, partial or deferred),
[recipes.md](../specs/nosh-v2/recipes.md), [security.md](../specs/nosh-v2/security.md)
(SEC-22, SEC-24, SEC-25, SEC-31 to SEC-42), [auth.md](../specs/nosh-v2/auth.md)
(AUTH-12, AUTH-14, AUTH-16), design §7 and the
[style log](../../restart/style-log.md). Mockups (git-ignored, main
checkout only): `C:\Users\Thoma\dev\nosh\.superpowers\brainstorm\1170-1795594147\content\empty-state.html`
(direction A) and `screens.html`.

## Global Constraints

- Worktree `.claude/worktrees/recipes`, branch `claude/recipes` (PR1). PR2
  works on `claude/recipes-url-photo`, cut from `claude/recipes` after
  Task 12.
- Strict TypeScript. `pnpm lint`, `pnpm typecheck` and `pnpm test` are clean
  before every commit. Tests are written red first.
- Every test title names the criterion IDs it covers, e.g.
  `it("REC-14 SEC-25: refuses HTML declared as image/png", …)`. Never
  renumber IDs. Tests for design-only rules (no ID) say `design §6.x`.
- Error bodies are `{ "error": "<message>" }`. Route answers use `c.json`,
  never `HTTPException` (onError turns any 4xx exception into "Invalid
  request").
- Spec-fixed copy, verbatim: `Recipe not found`, `Invalid recipe id`,
  `Collection not found`, `Delete this recipe? This can't be undone.`,
  `Failed to delete recipe`, `Replace this photo? The current one will be deleted.`,
  `Remove this photo? This can't be undone.`, `Failed to delete image`,
  `Failed to upload image`, `At most 30 tags`,
  `Press Enter or comma to add a tag.`, `Saving…`, `Something went wrong`,
  `New recipe`, `Edit recipe`, `Your library is empty` (COL-05),
  `No recipes match` (COL-05).
- Caps: title 200 characters, 100 ingredients, 100 steps, 30 tags, photo
  5 MB (5 × 1024 × 1024 bytes). Times and servings are whole numbers ≥ 1 or
  `null`.
- Look: design §7 and the style log win. Tokens already exist in
  `app/src/styles/tokens.css`; use them (never raw colours), so dark mode
  works. Motion constants come from `app/src/lib/motion.ts`.
- Recipe ids are integers. A path id that isn't a positive whole number is
  400 `Invalid recipe id`; one above 2147483647 is 404 `Recipe not found`
  (it can't exist).
- No push, PR, merge or production action without the owner's yes at that
  moment. PR2 never merges before Task 16.

## Review Focus

1. **A huge or odd path id** (`/api/recipes/99999999999`, `/api/recipes/1e3`,
   `/api/recipes/01`): 404 or 400, never a 500 from Postgres. Test in Task 4.
2. **A decompression bomb**: a small PNG declaring 9000 × 9000 pixels must
   be refused with 400 `That image is too large to process`, never exhaust
   memory. Test in Task 1 and Task 6.
3. **Tags differing only by accents or case** ("CRÈME", "crème", " Crème "):
   one tag, and the unique index never throws (JS `toLowerCase()` on both
   write and filter, never Postgres `lower()` on one side only). Test in
   Task 4.
4. **Double-tapping Save** on the create form: exactly one POST, one recipe.
   Test in Task 10.
5. **Two photo uploads racing on one recipe**: both answer 201 or one
   cleanly fails, the recipe ends with exactly one cover, and no file is
   left on disk without a row. Test in Task 6.
